# 02 AI 協作與提示詞

## 分工

| 角色 | 負責 |
|---|---|
| **作者（人）** | 決定要做什麼、玩法與美術方向、要不要花錢；在自己的電腦和 VPS 上執行指令、回傳結果；試玩並驗收 |
| **ChatGPT** | 需求討論：把想法整理成條列規格（規則、限制、驗收條件）；排錯引導：協助判讀錯誤訊息與截圖、整理要回報給 Claude Code 的內容 |
| **Claude Code** | 讀取專案、實作程式、寫測試並執行、用無頭瀏覽器截圖檢查畫面、Git 提交；部署時產生一批批的指令，並在 Windows 端做外部網路驗證 |

> 分工依作者說明整理。本紀錄的過程證據來自 Git 歷史與 Claude Code 的開發對話；ChatGPT 端的對話沒有收錄在這裡，所以不描述它的具體內容。

### 實際的工作流程

1. 作者和 ChatGPT 討論想法，整理成一份**條列需求**（要做什麼、保留什麼、限制、怎麼驗收）。
2. 把需求貼給 Claude Code。Claude Code 先讀現有程式與進度紀錄，再實作、測試、提交。
3. 作者試玩或看截圖，有問題再描述給 Claude Code（必要時先請 ChatGPT 幫忙整理）。
4. 需要在主機上操作時，Claude Code 一次給**一小批**指令，標明在「Windows PowerShell」或「VPS SSH」執行；作者執行後貼回結果，再給下一批。
5. 每個階段結束，把進度、測試結果和**還沒完成的事**寫進 `PROGRESS.md`，下次從那裡接續。

### 這個專案學到的原則

- **先保存再修改**：大改版前先 Git 提交或打標籤，改壞了可以回去。
- **把「保留什麼」寫清楚**：每次需求都列出不能改壞的功能（例如「保留 8 人、電腦玩家、30 張卡片」）。
- **說好怎麼驗收**：「完成後測試卡牌互動、技能冷卻、逾時及斷線重連」比「做好一點」有效得多。
- **測試通過 ≠ 外觀正確**：美術要看截圖、和參考圖並排比較。
- **看不到就說看不到**：要求 AI 收不到圖片或檔案時明說，不要假裝已參照。
- **花錢和不可逆的操作先停下來問**：建立收費資源、刪除資料、重啟公開服務、修改主機設定，都要作者明確同意。
- **一小批、等結果**：主機操作每批只做一件事，看到結果再繼續；只讀檢查和修改分開。
- **機密不進對話**：密碼、Token 由作者自己在官方網站或終端機輸入，不貼給 AI。

## 可重複使用的提示詞範本

把 `〈 〉` 換成自己的內容。這些範本整理自本專案實際用過的需求寫法。

### 1. 開新專案（第一版）

```text
請擔任遊戲開發工程師，協助我製作〈一款原創的網頁遊戲：類型〉。請直接開始實作，讓我先玩到第一版，再逐步擴充。

【開發方式】
1. 全程使用繁體中文說明與介面。
2. 我是初學者，操作步驟請清楚說明。
3. 使用 HTML、CSS、JavaScript；第一版不需要後端、付費服務或 API 金鑰。
4. 使用原創角色、地圖與名稱。
5. 完成後告訴我怎麼開啟試玩，以及目前支援與不支援的功能。
```

### 2. 加入新功能（在既有專案上）

```text
請在〈專案路徑〉的現有遊戲加入〈功能名稱〉。先讀取 PROGRESS.md 與目前程式，再直接實作。

保留：〈不能改壞的功能，例如 8 人、電腦玩家、存檔〉。
規則：
1. 〈規則 1：數值、時機、持續時間、限制〉
2. 〈規則 2〉
3. 結果由伺服器決定，前端不能偽造；重送與連點只結算一次。

驗收：
- 測試〈列出要測的情況，例如逾時、斷線重連、同時操作〉。
- 提供實際畫面截圖。
- 完成後提交 Git，更新 PROGRESS.md，清楚列出完成內容、測試結果與尚未驗證事項。
這次只做本機修改與測試，不要重啟公開服務。
```

### 3. 回報錯誤（請 AI 排錯）

```text
〈功能〉出現問題：〈看到的現象〉。其他部分〈仍正常的部分〉。

重現步驟：
1. 〈步驟〉
2. 〈步驟〉

請先讀取我附的截圖／錯誤訊息，檢查〈Console 錯誤、資源載入、相關資料〉。
請查證是否與〈我懷疑的原因〉有關，不要直接假定原因。
修正後用同樣的步驟重現確認，並補一個能防止再發生的測試。
```

### 4. 美術或外觀調整（依參考圖）

```text
〈角色〉的外觀不符合參考，請重做比例，不要只微調。保留已完成的技能與其他功能。

參考圖：〈本機完整路徑〉。請先讀取並描述你看到的內容讓我確認；如果讀不到，請明確告知，不要自行猜測。

目前的問題：
1. 〈比例〉
2. 〈五官〉
3. 〈手腳姿勢〉

完成後把參考圖與新模型的正面、四分之三、側面、背面放在同一張比較圖給我確認。
這階段不要把「程式測試通過」當作「外觀符合參考」。
```

### 5. 費用確認（部署前）

```text
我想讓朋友在我電腦關機後也能用固定網址遊玩。
請先核對〈平台〉官方目前的費率、付款與部署條件，列出主機、磁碟、流量的每月估計費用。
先完成部署前檢查；請先不要建立收費資源，等我確認方案和費用後再部署。
部署完成後，必須驗證多人連線及服務重啟後的房間恢復，才能回報正式完成。
```

### 6. 一步一步部署到 VPS

```text
請接續 PROGRESS.md 的部署進度，部署到我的 VPS。保留現有 SSH 與〈其他既有服務，例如 VPN〉設定，不建立其他付費資源。

每次只提供一小批指令，清楚標示在「Windows PowerShell」還是「VPS SSH」執行，等我回傳結果再繼續。
只讀檢查和修改分開；會影響連線或需要重開機的步驟，先說明影響再讓我決定。
不要要求我把密碼或 Token 貼進對話。
```

### 7. 暫停並記錄進度

```text
我要先休息。請把目前進度、已完成與待驗證項目、下一步指令寫入 PROGRESS.md，方便下次接續。
還沒確認執行完成的步驟，請不要標記為完成。
```

### 8. 公開前檢查

```text
我想把〈內容〉公開到 GitHub。請先在本機準備草稿，原本的儲存庫保持私人。
1. 只記錄有證據的內容，不要編造日期、測試結果或完成狀態。
2. IP、帳號、Email、主機資訊改成範例；不包含密碼、Token、API Key、私鑰、.env 或使用者資料。
3. 截圖先檢查私人資訊；確認素材的來源與授權，未確認的先排除。
4. 先給我預覽和預計公開的檔案清單，確認後再發布。
```
