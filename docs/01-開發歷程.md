## 遇到的問題與解法

| # | 問題 | 原因 | 解法 |
|---|---|---|---|
| 1 | 說好做 3D，畫面卻還是平面方格 | 瀏覽器開到舊版入口（同時有 2D 與 3D 版） | 先查網址、連接埠、伺服器對應的資料夾與分支；之後移除舊版入口，舊網址導向新首頁 |
| 2 | 分享腳本在 Windows PowerShell 5.1 執行失敗、中文亂碼 | 沒有 BOM 的 UTF-8 檔被 PowerShell 5.1 用系統編碼（Big5）讀取，中文吃掉後面的引號 | 腳本改成**純英文（ASCII）**，說明文字放到 README |
| 3 | 透過臨時通道時，大檔案（3D 程式庫）下載不完整 | 紀錄只寫了修正方式（右欄），沒有留下詳細原因分析 | 回應加上 `Content-Length` 並啟用 gzip 壓縮 |
| 4 | 加入電腦玩家後，3D 棋盤整個消失只剩背景 | 依作者提供的重現步驟（1 真人＋1 電腦、第一回合事件直接移動）追查；紀錄只留下修正內容（右欄） | 鏡頭數值防呆、WebGL 內容遺失時重建、全圖模式固定 |
| 5 | 視窗切到背景後，動畫佇列卡住 | 瀏覽器在背景分頁會暫停畫面更新 | 補間動畫改成依時間自動完成 |
| 6 | 雲端平台部署前要求綁信用卡 | 平台政策；官方也沒有花費上限 | 先比較費用、確認沒有建立收費資源，再改用已有的 VPS |
| 7 | VPS 只有 512 MB 記憶體、沒有 Docker | 小主機 | 不用 Docker：Node.js 官方版本＋systemd，設定記憶體上限；Windows 先打包好，VPS 不用安裝 npm |
| 8 | AI 說「已參照圖片」但其實沒收到圖 | 圖片沒有成功附上 | 在需求裡寫明「看不到附件請明確告知，不要假裝已參照」；把圖片放在專案資料夾、給完整路徑 |
| 9 | 角色外觀「做成可愛公仔」，和參考圖比例不符 | 只照文字描述做，沒有對照參考圖 | 讀到參考圖後**整個重做**模型比例；用「參考圖＋正面／四分之三／側面／背面」的對照圖確認 |
| 10 | 畫面有點糊（Windows 顯示比例 125%） | 3D 文字看板解析度不夠 | 文字看板改用 2 倍解析度，主畫面提高渲染解析度；用相同螢幕條件截圖比對 |
| 11 | 改預設地圖後，13 個舊測試失敗 | 舊測試依 28 格地圖的格子位置寫 | 測試用的伺服器固定 28 格；另外新增一項「新房間預設 64 格」的測試 |
| 12 | 在乾淨資料夾驗證時，某個測試大約 5 次失敗 1 次 | 測試把對手現金收到 0，之後隨機擲骰偶爾讓對手破產、對局提前結束 | 測試在驗證完後把對手現金補回；連跑 25 次都通過 |
| 13 | 本機 3000 連接埠被別的程式占用 | 其他專案在用 | 不動別人的程式，測試伺服器改用其他連接埠 |
| 14 | VPS 上有一條防火牆規則不在 ufw 裡，重開機後會不會消失？ | 規則由另一個自訂服務在開機時加入 | **重開機前先用只讀指令查清楚來源與啟動順序**，確認會自動加回才重開 |
| 15 | 上傳到 VPS `/tmp` 的檔案可能不見 | Debian 13 的 `/tmp` 在記憶體裡，重開機會清空 | 上傳後在同一次開機內完成安裝；安裝前再核對一次 SHA256 |
| 16 | 搬家後刪除舊資料夾，之後想再比對時已無法還原 | 當時是直接刪除 | 之後的刪除一律先備份或移到資源回收筒，確認可還原再刪 |
